# Shared-Position-Integrity-OMS

Reproducible simulation repository for the study:

**Shared Position Integrity under Asynchronous State Visibility:  
A Lifecycle-Aware Simulation of Control Policies for Heterogeneous Order Management Systems**

## Overview

This repository contains the complete simulation code, executed experiment outputs,
figures, and reproducibility materials for the R1 study on shared-position integrity
across heterogeneous order management systems (OMSs).

The study compares five control policies under asynchronous state visibility:

- **P0 — Independent Check**
- **P1C — Corrected Global Lock**
- **P2S — Static Escrow**
- **P2D — Dynamic Escrow**
- **P3 — Integrated Reservation**

The final lifecycle model includes:

- order arrival and admission
- stale-state observation
- partial fill with residual reservation
- full fill
- cancellation
- duplicate submission
- ACK loss / out-of-order acknowledgement
- terminal-report loss
- timeout
- authoritative reconciliation
- idempotency
- dynamic rights transfer

## Research Invariants

The final simulator enforces and tests the following invariants:

1. **Capacity invariant**  
   `executed + reserved <= position_capacity`

2. **Idempotency invariant**  
   The same order/reservation identifier must not consume capacity twice.

3. **Authoritative-release invariant**  
   ACK or timeout alone does not release reserved capacity.

4. **Residual-reservation invariant**  
   After a partial fill, only the executed quantity is released from reservation;
   the unfilled remainder remains reserved until further execution or cancellation.

## Final Main Experiment

The final main factorial experiment uses:

- OMS count: `2, 4, 8`
- propagation delay: `0, 2, 5, 10`
- load: `0.6, 1.0, 1.6`
- replications: `80`
- policies: `P0, P1C, P2S, P2D, P3`
- orders per episode: `180`

Total:

**14,400 policy-episodes**

## Important Interpretation Boundary

The latency variable in this repository is a **normalized service-cost metric**.
It is not a measurement of real brokerage or exchange latency in milliseconds.

The Dynamic Escrow policy is a **simplified rights-transfer heuristic**, not an
optimized or complete distributed escrow protocol.

The experiments are synthetic mechanism-level simulations and do not contain
real customer, account, brokerage, or exchange production data.
